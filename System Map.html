How a fact becomes memory

When something durable shows up, it gets routed — not just dumped. Four destinations, plus the trash. Then caps and consolidation keep the hot tier from ever growing.

2 · The 80% check & hard caps

Before any write to a capped section, I measure its char count. At ≥80% I don't append — I consolidate first: merge duplicates, tighten language, demote the oldest/lowest-value entries down to Recall. Bloat is structurally impossible.

4 · When consolidation runs

Cadence

  • ~Every 10 exchanges — self-triggered, no timer needed.
  • Session end — "wrap up" / "we're done".
  • 80% trigger — a capped section fills.
  • On demand — you say "consolidate".

The routine

  • Scan recent exchange.
  • Extract durable facts → route them (above).
  • Enforce caps (consolidate if ≥80%).
  • Harvest skills — flag complex/recurring/corrected tasks, ask "save this as a skill?"

5 · Recall — zero-cost retrieval

To answer something not in the hot tier, I spawn a subagent or grep over Recall.md + 00 Self-Management/** and return only the slice needed. Whole files never get loaded into main context just to look something up.

How I find things — without searching

Three reflexes depending on how specific you are. Names are the map; the Registry is the fallback. I plan + ask before a thorough directory sweep, but jump straight for a known file.

① Specific file mentioned

  • e.g. "use email-campaign-writer"
  • Check the Registry → jump straight to the file.
  • Read it. Execute. Token-efficient, direct.

② Domain mentioned

  • e.g. "show me marketing skills"
  • Read 00 Introduction to [Domain].md
  • Show what's available → wait for direction.

③ Project mentioned

  • e.g. "help with the webinar"
  • Read the project intro → check brain dump.
  • Understand context → ask what you need.
Read introductions first, always. Intro files explain a domain's philosophy and how to build in it. Index files list inventory only. Two different jobs — never merged.

Permission gate

  • Generating documents, modifying multiple files, or changing system structure → I ask first.
  • Reading one file or a light lookup → I just do it.
  • Thorough directory search → I plan + ask, then commit.

Intro file = philosophy

  • What the domain does + how to build in it.
  • References the index. No file inventory.
  • Frontmatter carries a dated change note.

Index file = inventory

  • What exists, what each does, when updated.
  • Existence and status only.
  • Updated whenever a file is added/removed/renamed.
Obsidian links match filenames exactly — [[email-campaign-writer]], never broken. New files = frontmatter only (date created/updated + # Title) until you specify what goes inside. Don't create files unless explicitly asked.
