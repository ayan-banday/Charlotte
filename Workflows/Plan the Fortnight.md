# Plan the Fortnight

**Problem:** Translate the yearly strategy (RGS) into an executable two-week plan, fast, without a 30-minute back-and-forth.

**Outcome:** A structured fortnight plan across 5 work types, every goal carrying a timeline, a binary win condition, and a named forcing function.

## Triggers

- "plan the fortnight"
- "two-week plan" / "plan the next two weeks"
- "monthly plan" (redirect: confirm two-week scope, this replaced the monthly version)

## Inputs

1. `[C] RGS.md` + `Context/Goals/RGS- Full details.md` — yearly strategy.
2. The current `00 Self-Management/Weeks/Week [ISO].md` — replaces the old "REDO" reference. Since Sept 15, 2026 this file spans two ISO weeks (e.g. `Week 38.md` covers Weeks 38–39). This is where reflections, patterns, and what's working/slipping actually live.

## The 5 Work Types

| Type | What it is |
|---|---|
| Infrastructure | One-time builds that unlock the next level (quarterly milestone work) |
| Long-term Infrastructure | Important-not-urgent multi-year projects |
| Skills | Daily practice + reflection to improve |
| Foundations | Health/habits requiring consistency (exercise, meditation, sleep) |
| Operational | Major one-time tasks this fortnight (exams, events, specific deliverables) |

## Requirements for Every Goal

1. **Timeline** — explicit date, not "this fortnight" vaguely.
2. **Win Condition** — one sentence, binary yes/no on the deadline. Starts with "Done means:". The title IS the win condition, stated as an event not a state.
   - Bad (state): "Midterm Mastery," "Content Consistency"
   - Good (event): "Score 80%+ on Sep 29 Midterm," "Publish First YouTube Video"
3. **Forcing Function** — a named person or mechanism. "None" only acceptable if truly self-driven with a clear internal trigger.
   - Bad: "Mock test completed"
   - Good: "Mock test reviewed with [Name] on Sep 28"

## Step 1: Setup

State:

"I'll help you build your fortnight plan across 5 work types. Every goal needs a timeline, a binary win condition, and a named forcing function. Paste your RGS if it's changed, and I'll pull the current Week file myself."

## Step 2: Extract Context, Surface Gaps

- Identify the current quarter and its milestone from RGS.
- Read the current Week file for what's working and what's slipping.
- Compare RGS barriers (Wedge, Distribution, Venture Readiness, People, Capacity) against what the Week file shows movement on. Surface the barriers with no movement.

Output format:

```
**Context:**
Current: [date range], [Quarter]
Q[X] Milestone: [Title + description]

**From the current Week:**
✓ Working: [brief list]
⚠️ Slipping: [brief list]

**Barriers with no movement this cycle:**
- [Barrier]: [why it matters now]
```

Keep to 3–5 surfaced areas max. Ask: "Any of these need a slot, or already handled?"

## Step 3: Build the Plan

Offer:

A. Brain dump all 5 areas now (I structure and ask only what's missing)
B. Go section by section

If brain dump is comprehensive (specific outputs, timelines, binary win conditions, named forcing functions) → structure immediately. If incomplete → ask only for the missing piece, one question at a time.

## Step 4: Format Check

Before compiling, verify every goal has: title = win condition (event, not state), explicit timeline, "Done means:" binary statement, named forcing function. Ask only for what's missing.

## Step 5: Compile

```
# Fortnight Plan — [date range]

## Priority 1: [Win Condition as Title]
**Timeline:** [date]
**Done means:** [binary statement]
**Forcing function:** [named person/mechanism] on [date/trigger]

---
[Repeat for Priority 2, 3...]

## Skills (Daily Practice)
**[Skill]:** [practice structure]
**Forcing function:** [named person or tracking method]

## Foundations (Scheduled)
**[Area]:** [time blocks]

## Operational Tasks
- [Task]
```

Ask: "Does this capture the fortnight? Any adjustments?"

## Guidelines

- Efficient, not a 30-minute conversation. Structure comprehensive input immediately, guide only when incomplete.
- Enforce the title-as-event rule. Push back on state-titles.
- Enforce named forcing functions. Push back on vague ones.
- Surface RGS-barrier gaps, don't lecture on them.
